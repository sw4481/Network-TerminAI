## Contract decisions shared by the tasks

Use snake_case fields on the existing wire; avoid a parallel case-conversion layer. Create one synthetic cross-language fixture under `tests/fixtures/copilot_canvas/v1.json` as the executable contract, not production seed data. Creating it does not authorize a Git commit.

- `CanvasRequest`: `{workspace_id: string, run_id: string, selection?: SelectedContext}`. The workspace ID **is a real persisted `tabs.id`**, with `tab_type = 'canvas'`, empty shell/cwd, and the existing Network Architect conversation bucket. It is not a terminal ID invented to satisfy an API.
- `CanvasEvent`: `{type: 'canvas', version: 1, workspace_id, run_id, seq, kind, payload}`. `seq` is a monotonic integer per run, allocated under the turn context's lock. Kinds: `card`, `coverage`, `warning`. IDs are application-assigned UUIDs. Routing captures workspace/run at turn start, not the currently selected tab.
- `EvidenceSnapshot`: `evidence_id`, `workspace_id`, `run_id`, `call_id`, `collected_at`, `source`, `origin`, `complete`, `limitation`, `data`, `parent_refs`, `calculation`. Collection time is application-assigned UTC RFC3339; any source timestamp stays in source data. `origin` is `observed`, `derived` or `execution_output`. Helper invocation IDs are not falsely described as LangGraph's own tool IDs.
- `EvidenceRef`: `{evidence_id: string, path: string}` using RFC6901 JSON Pointer only, including `''` for the root. Own JSON properties only; reject expressions, wildcards and inherited-property traversal. No JSONPath execution or general transformation language.
- `CardSpec`: type from `findings | table | key_value | chart | topology | text | assessment`, title, source references, and type-specific metadata. Observed identifiers/values are references, never model-provided cells. Findings carry reference-bound device/interface fields, explicitly interpretive symptom/severity/cause assessment, supporting/contradictory references, unknowns and remediation considerations. Cause enum: `evidence_supported | likely | undetermined`.
- `CanvasCard` extends validated `CardSpec` with application-owned `card_id`, `workspace_id`, `run_id` and `created_at`. `CanvasRun` has `workspace_id`, `run_id`, `status`, `started_at`, nullable `ended_at`, and nullable scope/coverage metadata. Status is `collecting | awaiting_approval | completed | failed | cancelled | interrupted`; save status is separate. `ResolvedCanvasCard` is the renderer-facing discriminated union with source values resolved from snapshots, including `ResolvedChartCard` for charts. Task 1 defines these types and the fixture; consumers do not invent parallel definitions.
- A `card` event carries an immutable card plus the redacted snapshots necessary to resolve it. Referenced snapshots remain pinned; unreferenced captures are temporary. Coverage events reference actual inventory/check assessments; counts are computed, and unknown denominator stays unknown. No unchecked model-authored totals.
- `SelectedContext`: selected card IDs plus bounded redacted relevant values with original evidence references and explicit omission metadata. Budget it inside the current context allowance, not on top. If the selection cannot fit meaningfully, visibly block send until reduced rather than silently drop a card. Older evidence retains its original identity/time; selection is not permission to execute.

Do not add configurable limits/settings. Derive capture bounds from the current tool-output policy: at most the existing 2 MiB retained-result allowance per snapshot **and per run's unreferenced capture cache**, UTF-8 measured conservatively; evict only unreferenced captures. Existing 48,000-character inline formatting and 30-second tool execution timeout remain unchanged. A captured item too large to retain is incomplete, not a valid full dataset. Bound emitted card batches to the same snapshot allowance and show a presentation limitation if necessary; no truncation into invalid JSON.
